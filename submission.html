Overview

I built a conversational ReAct agent with LangChain's initialize_agent (AgentType.CONVERSATIONAL_REACT_DESCRIPTION). It has two tools, a safe Calculator and a mock Search, a custom prompt template that tells the model when to use each one, and ConversationBufferMemory so follow-up questions can refer to earlier answers. The LLM is Google Gemini (gemini-3.5-flash through langchain-google-genai) with temperature=0, so tool choices are repeatable. LangChain keeps the agent separate from the model, so switching to another LLM such as OpenAI's ChatOpenAI means changing a single line. LangChain 1.x moved the legacy agent API out of langchain, so the imports come from langchain_classic; the classes are the same ones used in the course.

1. How I created the tools

Calculator (eval() made safe). Calling eval(input) on raw LLM output would run any Python the model writes, for example __import__('os').system(...). So the tool first parses the expression into an AST and rejects anything that is not plain arithmetic: numbers, + − × ÷ // % **, and a whitelist of functions such as sqrt, round and abs. Very large exponents are also rejected. Only then does it call eval(), with __builtins__ disabled. Before parsing, it cleans up input the LLM often sends: thousands separators (1,428,627,663), ^ for powers, and 23 x 5. Errors come back as text, so the agent sees them as an Observation and can retry.

Mock search. A small in-memory index of realistic snippets: capital of France, population of India and France, Eiffel Tower height, and a few more. The query is matched by keyword overlap after removing stop words, so "population of India", "India population" and "how many people live in India" all return the same result. Results are labelled [Mock search] and include a fake source.

Wrapping as LangChain tools. Each function becomes a Tool(name, func, description). The description is what the LLM reads when it chooses a tool, so each one says when to use the tool and what input format it expects:

Tool(name="Calculator", func=calculator_tool,
     description="Use for ANY arithmetic or math ... Input must be a single plain math
                  expression using numbers only, e.g. '23 * 5' or '1428627663 + 34'.")
Tool(name="Search", func=mock_search_tool,
     description="Use to look up facts about the world: capitals, populations, places ...
                  Input should be a short search query. Do not use it for math.")

2. Prompt strategy

The conversational agent builds its PromptTemplate as prefix + tool list + format instructions + suffix. I wrote a custom prefix and suffix, built the template with ConversationalAgent.create_prompt(...) so I could print and inspect it, and passed the same prefix and suffix to initialize_agent through agent_kwargs. An assert confirms that the agent uses exactly that template.

  • Role: "a careful research-and-math assistant that answers by choosing the right tool."
  • Explicit tool-selection rules: (1) any arithmetic goes to Calculator, never mental math; (2) world facts go to Search, never memory; (3) if a question needs both, search first, then pass the number found to Calculator, one tool per step; (4) if the question refers to something earlier ("my first question"), reuse the value from the conversation history; (5) greetings need no tool; (6) give a short final answer and name the tools used.
  • Suffix: injects {chat_history} (memory), {input} and {agent_scratchpad} (the model's previous Thought/Action/Observation steps).

Rule 1 matters most. Without it, the model answers "23 * 5" from its own knowledge and the Calculator is never used.

3. How the agent reasons and selects tools

The agent runs a ReAct loop (Reason + Act). On each step the LLM writes:

Thought: Do I need to use a tool? Yes
Action: Search
Action Input: population of India

LangChain stops generation at Observation:, runs the chosen tool, and appends its result as the Observation. Then it calls the LLM again with the updated scratchpad. The loop ends when the model writes Thought: Do I need to use a tool? No followed by AI: <answer>. The model chooses a tool by comparing the question with the tool descriptions and the rules in the prefix:

  • "What is 23 * 5?" is arithmetic, so it goes to Calculator.
  • "What is the capital of France?" is a world fact, so it goes to Search.
  • "Add 34 and search for population of India." is ambiguous: add 34 to what? The agent read the chat history and treated it as "add 34 to the previous result (115)". It called Calculator (115 + 34), then Search for the population. That is two different tools in one run, plus memory.
  • "Multiply the result of my first question by 2." finds 115 in {chat_history} (memory), then calls Calculator with 115 * 2.

A problem I found and fixed. In my first run with Gemini, tests 2 and 3 answered "I used Search", but the trace had no Observation: line. The model had written the Action and then kept writing, inventing its own final AI: answer in the same response. LangChain's default ConvoOutputParser checks for AI: first, so it accepted that answer and the tool never ran. I replaced it with a small custom parser (FirstActionParser, passed through agent_kwargs) that always executes the first Action and discards anything the model wrote after it. After that, every answer is grounded in a real tool Observation. Lesson: the claim "(Used Search)" means nothing unless the trace shows the Observation.

Settings: verbose=True prints every Thought/Action/Observation, handle_parsing_errors=True recovers if the LLM breaks the format, and max_iterations=6 stops runaway loops.
